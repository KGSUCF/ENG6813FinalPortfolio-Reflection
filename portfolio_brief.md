# Portfolio Brief for Claude Code

## Project goal

Build a polished GitHub Pages e-portfolio presenting a proposed undergraduate course:

**ENG 2011: Media Literacy in the Humanities**

The portfolio should look like a coherent course proposal and teaching portfolio, not a chronological archive of weekly graduate-course submissions. It should interest a hiring committee quickly while allowing a curious reader to explore artifacts, assignments, and design choices in more depth.

## Audience

Primary audience:
- Faculty, hiring committees, curriculum reviewers, and digital humanities educators.

Secondary audience:
- Prospective students interested in the course.

## Current course concept

**ENG 2011: Media Literacy in the Humanities** is an introductory undergraduate course that teaches students to read persuasive messages carefully, question evidence, recognize manipulation, reflect on their own interpretive habits, and use AI as a tool rather than an authority.

The course is humanities-based rather than journalism- or mass-communication-centered. It focuses on meaning-making, persuasion, rhetoric, visual and data interpretation, misinformation, AI, and public-facing communication.

## Site tone

Warm academic, accessible, lightly playful, and intellectually serious. The site should not feel corporate, generic, or childish. It should show that the course is rigorous but welcoming.

## Visual style

Use:
- warm ivory or soft paper background
- deep plum, purple, or indigo accents
- muted gold or warm accent highlights
- readable, accessible typography
- serif or humanist-style headings
- clean sans-serif body text
- clear navigation
- card-based artifact sections
- callout boxes for teaching principles
- accessible color contrast
- responsive layout for desktop and mobile

Avoid:
- dense walls of text
- generic corporate blue templates
- overuse of animations
- visual clutter
- making every artifact equally prominent

## Preferred site structure

Create a multi-section or multi-page site with these areas:

1. **Home / Course Vision**
2. **Course Overview**
3. **Learning Objectives**
4. **Syllabus & Course Map**
5. **Signature Assignment**
6. **AI Policy & Access**
7. **Teaching Artifacts**
8. **Teaching Statement**
9. **Final Reflection**

## Current artifact decisions

Feature:
- **Point Taken** as an instructor-created fallacy game used in Week 4. Make clear students play it but are not expected to create an agentic game like it.
- **1% Tax Visualization** as the primary data-rhetoric example. It is preferred over the Vietnam visualization because it is less historically/politically complex and more directly shows same data / different framing.
- **Lincoln Speeches Explorer** as a digital humanities / public-domain corpus / Claude Code example.
- **AI Policy Cartoon** prominently in the AI Policy & Access section.

Do not feature as a main artifact:
- The old Week 8 signature-assignment portfolio. The new final e-portfolio replaces it. It may be mentioned only as a prototype if needed.
- The Vietnam visualization, unless used in an optional/additional experiments gallery.
- Every weekly graduate submission as its own page.

Optional secondary artifacts:
- Pulitzer photo visual analysis
- fairy-tale Voyant/text-analysis work
- guitar persuasion Artifact
- Friends persuasion Artifact
- Bloom's taxonomy visualization
- Vietnam visualization

## Source of truth

Use this brief and the included Markdown files as the source of truth. If weekly submissions are uploaded later, treat them as background only unless I specifically ask you to pull content from them.

## Technical expectations

Build a static site suitable for GitHub Pages. Use simple, maintainable HTML/CSS/JS or a lightweight static framework only if already present in the repository. Avoid unnecessary dependencies. The site should be easy to edit manually.

Include clear placeholders for missing artifact screenshots or links.
